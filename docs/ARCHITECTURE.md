# Source and authority

Project Version: 0.10.0-dev.1

[VERIFIED source] `src/B47ANCEDPCFramework` is authoritative. `42/media/lua/client/B47ANCEDPCFramework` owns the desktop, app registry and world menu/navigation. `B47ANCEDPCUI` is an isolated copy of B47ANCE's owned embedded UI helpers, renamed to avoid overriding app UI or appearance files. Shared `Device.lua` recognizes all four native desktop orientations and other `CustomName=Computer` tiles, then validates loaded identity, adjacency, native power and multiplayer safehouse access. Shared `DriveService.lua` is called only through a consumer's authenticated server service. No `require` or reverse dependency on Quartermaster exists in runtime source.

The desktop and pending navigation are local presentation; they persist no gameplay. App factories and proxies are trusted local presentation objects, never sender identity or server grants. Domain apps own their server transport, privacy, ledger/media interpretation, inventory mutation, timing and synchronization. The bundled Minesweeper app now supplies its own server-authoritative command service, described below; desktop/UI factories remain presentation-only. Framework discovery/mount/eject bindings are server-owned through callback contracts; clients submit tokens, never trusted inventory claims.

Original extraction baseline: Quartermaster commit `77ee0ebf43a74db299db60576fb504cedae35659` (0.18.0-dev.2). Sources: `ComputerUI.lua`, the native-world helpers from `LedgerMedia.lua`, `LedgerDrives.lua`, and the owned `B47ANCEDUI` helpers. These are B47ANCE project files, not external-mod code or assets. The CD writer's ledger-specific UI remains in Quartermaster. Runtime APIs are existing Lua-exposed native methods; no Java code is added or required. Source fingerprints are recorded in `PROVENANCE.json`.

Quartermaster adapter retains `B47ANCEDQuartermasterLedgerDrives` schema 1, `B47LedgerDrive` and `B47LedgerDriveStorage`. Existing records are read in place by the extracted server engine; there is no destructive migration, snapshot rewrite or copying to a second store. Its ledger items and snapshots remain Quartermaster-owned. Old counterparts cannot join the new dependency combination safely; use matching peers and reconnect. Downgrading source does not require a reverse data migration because stored formats and command names are unchanged; actual native save rollback remains untested and backups are required before runtime testing.

New apps must choose their own stable store and object keys and document their schema. Corrupt/future records are preserved and rejected. Framework disabling retains records. Every grant/read rechecks current access, real media, loaded-object identity and power. Join/reconnect, unloaded chunks, restarts, multi-app contention and real inventory notification remain native runtime gates.

Source inventory: `scripts/production-files.json`. Generated ZIPs and SHA-256 receipts belong under ignored `dist/current/`; artifacts are built only on explicit request. Packaging checks and generated output cannot replace source or native evidence. Exact fallback PNG bytes were decoded and SHA-256/dimension checked against installed team branding; see `BRANDING.json`.

Powered-PC support 0.2.0-dev.1 is a compatible MINOR expansion from 0.1.0-dev.1; registration API and binding schema remain 1. Native `appliances_com_01_72`/73/74/75 are the S/E/N/W PC orientations. Other placed tiles qualify only through exact, nonlocalized `CustomName=Computer` sprite metadata. This avoids English display-name and sprite-name substring guesses. Modded PCs without that metadata cannot be identified safely; they must declare it in their tile definitions on server and clients. Merely standing beside a powered appliance or carrying a computer item does not qualify. Recognition is read-only on each peer; authoritative app operations still revalidate the server object. Hardware identity is a compatibility contract rather than a gameplay setting; the existing server Enabled switch still governs all devices.

Public UI SDK 0.3.0-dev.1 is a compatible MINOR expansion. Client `UI.lua` owns reusable native PC controls and hosted-window lifecycle; `Assets.lua` owns isolated palette tokens and original scalable drawings/custom drawing registrations. ComputerUI now consumes these modules, so desktop rendering and public consumers share the same component primitives. Application API 1 and the Quartermaster media factory remain supported; UI and drawing-assets contracts are independently versioned at 1. Public version/capability queries return copies. The additive installed-app descriptor is trusted Lua registration and does not load programs from physical media.

Installed-app availability is read-only. Explicit launch creates one hosted SDK window. Context guards recheck current actor, desktop/window identity, device power/access and app privacy before applying UI callbacks. Close/builder errors invalidate callbacks and clean up children before propagating errors. This does not authenticate gameplay intents, cancel a consumer's server jobs, or replace server authorization. Window positions, metrics, palette/drawing rules and callback scheduling remain presentation/implementation details; no gameplay option is added. Framework Enabled stays server sandbox configuration. Apps still own gameplay data, meaningful server options, network protocols, migrations, reconnect/restart and cross-app media coordination. The example and brainstorm are separate from packaged runtime; no proposed gameplay contract is silently implemented.

The additive roadmap controls (`tabView`, `toolbar`, `statusBar`) compose existing native panels/buttons and keep only local selection, layout and text. Pages remain attached but hidden when inactive; consumers rebuild hosted focus rows using only the active page. No gameplay persistence, schema, transport, access callback or server setting changes are needed. Native rendering/input remains a runtime gate.

CD program SDK 0.5.0-dev.1 is a compatible MINOR addition. Client `registerCDProgram` shares private `ProgramContext.lua` lifecycle with installed apps, preserving API 1 behavior. It checks a one-shot, time-bounded reply against the exact requested program/version/item/binding before constructing UI. Shared `CDPrograms.lua` exposes contract 1 and an explicitly server-used registry over an existing DriveService. Server list/authorize/resolve revalidate PC, real item, exact binding, adapter access/snapshot, type and pure program acceptance. Replies omit server objects and private snapshots; `resolve` stays server-only and must run again for every gameplay operation. No durable launch grant, new persisted state, universal item type, burner or framework command transport is added. Definitions must be re-registered and bindings rediscovered after restart/reconnect. Existing binding namespaces/schema and Quartermaster writer/media protocol stay unchanged. The new 15-second pending-UI timeout and bounded descriptor sizes are internal protocol safety constraints; meaningful program gameplay configuration remains app-owned server sandbox settings. Native SP/dedicated remains NOT TESTED.

Bundled Minesweeper 0.6.0-dev.1 is local client presentation/puzzle state. Startup installs `b47pc.minesweeper`; pure board rules and the public-SDK app live in client `Apps/`. Each context allocates a new board and timer, discarded on close; it creates no ModData, world/item mutation, network traffic, saved score or reward. Thus no shared game state is assigned to the client. Fixed 9x9/10-mine rules define the bundled puzzle; temporary flag mode/window geometry need no server gameplay settings. Framework Enabled/power/privacy still gate the host and every guarded input. Public registration APIs and persisted formats stay unchanged. The original app and English fallback strings are included in the production manifest; opt-in examples are excluded.

Minesweeper 0.7.0-dev.1 replaces the prior local-only board with an ephemeral server/SP session and bounded mood service. Shared board rules retain their require name. Clients send sequenced legal-move intents; the server revalidates loaded/near/powered/authorized PC identity and owns progress clocks, settings and stats. Hidden board data is redacted; native stat removal and owner synchronization are source-audited. No client setter, custom Java, persisted game record or custom stat packet is added. Public app/CD contracts remain unchanged. See MINESWEEPER_MOOD.md for default rates, sandbox validation, inactivity/replay handling, restart/reconnect ownership and dedicated gates. The 0.6 local-only description above is historical behavior, not the 0.7 authority model. The prior package is preserved, and this source iteration is not automatically repackaged or deployed.

Seated access 0.8.0-dev.1 is an additive MINOR expansion with unchanged API/schema versions. Shared Device validates native sitting state, the exact loaded occupied furniture, native seating data, front-facing position and bounded actor-to-seat/seat-to-PC reach. Original adjacent access is retained. Native RestAction records the furniture client/server; native sitting-state processing owns its flag and animation position. The framework only reads this state and adds no packet, persistence or migration. Server operations never trust client seat claims. Startup opens immediately when reachable, preserving queued rest, and refuses automatic walking while seated. Endurance/rest progression remains vanilla-owned. These fixed physical-access constraints need no new balance setting; Enabled and existing app sandbox settings still apply. See SEATED_PC.md and SEATED_PC_API.json. Actual seating synchronization and simultaneous rest/app behavior remain native SP/dedicated gates, not source-verified runtime behavior.

Unified desktop 0.9.0-dev.1 adds client-only Desktop.lua and CRT.lua. A single native root owns independent app/tool host facades, panels, closures and media proxy state. Startup now supplies one world action; API registration feeds the common desktop/Start catalog. Session liveness replaces foreground identity in SDK/CD guards. App-only access loss retires that app; global device/actor/power loss tears down all sessions, completing cleanup before raising an error. The root uses original Lua CRT/pixel geometry from the approved design. No server command, reward, item transaction, saved state, schema or sandbox value changes. Fixed UI coordinates/paging/span caches remain internal presentation. Existing UI_NATIVE_API.json source evidence applies to the reused native rectangle/text/widget methods; no new engine API is assumed. See UNIFIED_DESKTOP.md and CRT_DESIGN.json.

In 0.10.0-dev.1 the private CRT shell draws the whole front-facing PC with uniform scaling, a 4:3 live screen and decorative keyboard/mouse/system case. Native app controls, callbacks and server authority are unchanged. Existing crt-frame/UI/assets API 1 contracts remain compatible. The native root includes hardware outside the usable monitor surface, so app layout must use its hosted content panel dimensions; widening a height-limited root centers the PC instead of stretching it. Font-aware root minimums preserve readable consumer content. No new engine drawing calls, network state or sandbox options.
