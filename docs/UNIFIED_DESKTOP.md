# Shared Windows '93 desktop

Project Version: 0.11.0-dev.1

The native world action opens one desktop for the current player and PC. Every registered, enabled, currently authorized app appears on that desktop and its Start menu. Installed apps launch explicitly from either place; media apps open their CD browser and still require a real compatible mounted CD and explicit EXE/Run authorization. No app is automatically run when the computer opens. App registration after opening is discovered during the bounded two-second catalog refresh. Unavailable apps are omitted; availability callbacks must remain pure. Large catalogs page identically in both launchers, and taskbar buttons page independently when needed.

The current shell shows the PC in a straight-on 2D front view inspired by the supplied PC artwork: aged beige CRT and horizontal system unit with drive bays/front vents. There is no keyboard or mouse artwork. The shared teal desktop, app windows, Start menu, status and taskbar stay inside the 4:3 monitor screen. CRT.lua contains editable normalized Lua geometry on a compact 1000 by 840 canvas; it caches polygon spans once and uses the existing rectangle/text APIs. Uniform scaling centers the PC without stretching its proportions. The case power control retains local logoff only; the other hardware artwork is decorative and grants no gameplay/input authority. Large fonts require a larger whole-PC window; unsupported viewports retain the existing localized size hint. Geometry, bounded drawing, minimum dimensions and letterboxing are internal presentation constraints, not sandbox settings. Original references and the current front-view decision are recorded in CRT_DESIGN.json.

Each registered app has an independent host session in the same native root. Its hosted panel, callback closures, pending CD authorization, mounted-media proxy, polling time and status belong to that session. Switching apps restores their existing windows; it does not close or reconstruct them. A legacy writer/tool gets its own session/taskbar window, so it can coexist with its provider's CD/ledger window. One SDK `ctx.window` per app remains the contract. Windows currently share the content area; arbitrary independent drag/snap and multiple SDK windows per app remain future work.

`PC.open(playerNum,computer)` opens the common desktop. Passing an ID focuses/creates its app session without launching it, retaining API-1 callback behavior. `ComputerUI.active[playerNum]` is the focused host for legacy consumers, while `ComputerUI.desktops[playerNum]` owns the shell. A host is a session facade; geometry/input methods delegate to `host.root`, the native ISUI window. Use `ComputerUI.isLive(host)` or `ctx.isActive()` for lifecycle checks, rather than interpreting foreground identity as the lifetime of another app. `ctx.guard` works for a retained/minimized app and is invalidated by closure, actor/PC replacement or access loss. Reopening the same ID returns its existing session. Registry IDs, including `desktop`, do not collide with private home/tool session keys. Additive capabilities are `unified-desktop`, `retained-app-windows` and `crt-frame`; application/UI/assets/CD contracts remain 1.

The common CD-ROM shortcut opens the first available provider in stable app-ID order. When several providers exist, the browser has an app/provider selector. It switches to that provider's independent session; it never mixes opaque offers, bindings, private snapshots or commands. No global hardware lock or item ownership is inferred from the UI. Each owning server adapter must continue validating genuine media, power, permissions and every gameplay operation. A late reply from a replaced/closed browser cannot replace another window. Drive polling remains bounded per opened provider.

Closing/minimizing one panel preserves other apps. Losing an app's permission or enable state retires only its sessions and runs their teardown; the independent desktop remains. Power/framework disable, invalid PC/seated reach, death, actor replacement, logoff or switching PCs closes the whole root and every session, completing cleanup even when one app's cleanup raises. Physical power is local logoff, not a world electricity switch. No desktop/session/window state is saved; native/server gameplay records retain their existing ownership and schemas. Reconnect/restart requires fresh authorized app/media discovery.
